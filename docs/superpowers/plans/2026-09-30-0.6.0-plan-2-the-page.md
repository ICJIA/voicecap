# voicecap 0.6.0, Plan 2 of 6: The Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every site folder gets `share/current.html`: one self-contained page that shows the site's standing from its sealed runs, the person's review, every problem with its record, what changed since the run before, and the evidence, with a fingerprint check that works offline.

**Architecture:**
- **Pure functions over the site's records**, each in its own module: the standing, the problems, the changes since the run before, the human review and summary, the fixed text, and the fingerprint check's data and script.
- **`buildShareModel`** composes them into one `ShareModel`, which `loadShareInput` feeds from the site folder.
- **Section renderers** in `src/share/html/` turn the model into markup with the approved mockup's design.
- **`renderSharePage`** assembles one file: one style block, embedded fonts, and small scripts.
- **`writeSharePage`** writes `share/current.html` wherever `report.html` is written.

**Tech Stack:** TypeScript (strict, ESM), Node.js 22.19+, Vitest; `diff` (already a dependency) for line and word changes; Playwright Chromium and axe-core in the tests (already dev dependencies); IBM Plex Latin woff2 files from `@fontsource/*` 5.3.0 (OFL-1.1), copied into the repository.

**Spec:** `docs/superpowers/specs/2026-09-30-shareable-report-design.md`. All of it bears on the page except "Repeating a walkthrough" (plan 4), "Files, names, and the record of what was sent" and "The Word copy" (plan 3), "The website" (plan 5), and evidence A, B, and C (plan 6).

**Design:** `docs/superpowers/specs/2026-09-30-shareable-report-mockup.html`, the approved mockup.
- Its markup, class names, style block, and scripts are the page's design. Port them; don't reinvent them.
- Everything inside an element with class `mock` is sample data or a note about one. It never appears in a real page.

## The 0.6.0 plans

1. **Run records:** done (merged 2026-09-30).
2. **The page (this plan):** the share model and its parts, the fixed text with the timeline, the fingerprint check, the page with its folds and fonts, and `share/current.html` written wherever `report.html` is (after a completed run, a review, a manual session, and `voicecap report`).
3. **The Word copy and sharing:** `docx.ts`, `current.docx`, `voicecap share` and the dated copies, `shares.json`, the paste line, and `verify`'s checks.
4. **The walkthrough file:** `voicecap walkthrough`, `--walkthrough`, and the page's download.
5. **The website:** `voicecap site`, with the `netlify.toml` and `.nvmrc` it writes.
6. **Stage 2, at the PC:** evidence A (`events.jsonl` and the program in front), B (screenshots), and C (NVDA's own log and the cross-check).

## Global Constraints

- **Toolchain:**
  - Node.js 22.19 or later; TypeScript strict; ESM; pnpm.
  - `pnpm lint` (ESLint, then Prettier), `pnpm typecheck`, and `pnpm test` all pass before each commit.
- **One self-contained file:**
  - Styles, fonts, SVG charts, and data are all inside it. Nothing is loaded from outside the file.
  - The only links out are `https://github.com/ICJIA/voicecap`, `https://github.com/ICJIA/voicecap/issues`, `https://www.nvaccess.org/`, and the Deque study the story cites.
- **Netlify's policy (plan 5):** exactly one `<style>` element and no `style="…"` attribute anywhere, SVG included, since plan 5's Content Security Policy hashes the style block and the scripts.
- **Themes:** dark by default, light when switched, light in print.
- **Folds:**
  - Folds are `<details>` and `<summary>`.
  - Section headings (`h2`) are never inside a fold.
  - A `<summary>` never contains a heading.
  - Headings inside a fold start at `h3`.
  - Every scrolling box can be reached with the keyboard (`tabindex="0"`) and has a name.
- **Color is never the only signal:** every chip and bar label says its status in words.
- **The page is complete without JavaScript:**
  - Its only scripts are the theme button, "Open every section", opening every fold for printing, opening a fold a link points into, and "Check the fingerprints".
  - Without them, every fold still opens by hand.
- **axe:** zero violations on the generated page, with every fold closed and with every fold open, in both themes.
- **Fonts:** IBM Plex Sans, Sans Condensed, and Mono, Latin subsets, embedded as `data:font/woff2` URIs. The OFL text ships with voicecap.
- **Honesty** (the spec's rules, binding on every sentence the page computes):
  - voicecap is a person's review with a real screen reader, sped up. Never "automated testing" or an "automated checker".
  - The page says a person listened, reviewed, or fixed something only where the records say so, and never leads with what a person hasn't done.
  - Coverage is claimed for the list ("every page on the list"), never "every page on the site", unless the list is the site's whole sitemap.
  - Every page in scope appears. Failures appear with their reasons and records.
  - A problem's kind comes from its cause code or from voicecap's own wording, never a guess. An error voicecap didn't expect shows as possibly voicecap's own.
  - Every number is computed from the records.
  - Unfinished, unsealed, and replayed runs never count, and the page says what it left out.
  - Where a run predates a kind of evidence, the page says "Not recorded: this run used voicecap <version>", never a blank.
  - Flags are rules that point a person to pages worth a closer listen; the person reviewing decides what they mean.
  - No claim of conformance (such as "meets WCAG").
- **The home folder** is replaced (`redactHome` from `src/run/failure.ts`: `%USERPROFILE%` on Windows, `~` elsewhere) in every message, path, and stack the page shows. The recorded files stay as they are.
- **Copy:**
  - Curly quotes for quoted speech (“click here”).
  - Dates as "30 September 2026", or "29 September" where the year is plain.
  - Times as 24-hour local "13:15".
  - Counts as digits.
- **The timeline lives in `src/share/text.ts` from this plan on.** When a major feature lands, its line goes in the same change.
- **Never start a real screen reader,** in tests or while building:
  - no run without `--replay-from` or a scripted driver;
  - no `setup`, `doctor`, `demo`, `init`, `test:nvda`, or `fixture:capture`;
  - never pass a composed command through `cmd /c` or any shell.
- **Commit messages:** no trailers (no `Co-Authored-By`, no `Claude-Session`).

## Review Focus

1. **A site with no run that counts** (only replayed or interrupted runs, as in CI's smoke test): the page still writes, says that no live run counts yet, and lists what it left out. Tasks 1 and 13 add the tests.
2. **A transcript containing `</script>`, `<!--`, or markup such as `<b>`:** the appendix shows it as text, the embedded data survives it, and the fingerprint check still matches. Tasks 6 and 13 add the tests.
3. **Runs recorded by 0.4.1 or 0.5.0:** they have no titles, attempt records, computer, or listener's statement. Every such place says "Not recorded: this run used voicecap <version>", and problems take their kind from the recorded wording. Tasks 2 and 7 add the tests.
4. **A site of more than 12 pages with many flags:** pages with nothing to note fold away, and so do the flag quotes past 3 flagged pages. Pages that need attention always show. Task 9 adds the tests: string-level, on the markup. The browser tests in Task 13 check the scripts that open the folds.
5. **A page whose latest attempt failed, with good transcripts from an earlier run:** the card shows the failure beside the older transcripts, the appendix shows those, and the fingerprint check uses the older run's record. Tasks 1, 7, and 13 add the tests.

```ts
export type ProblemKind =
  | "foreground" | "locked" | "screen-reader-stopped" | "browser" | "http" | "unreachable" | "timeout" | "unexpected";
export interface ProblemRecordRow { time: string | null; source: "run.json" | "stack"; entry: string }
export interface Problem {
  run: string;
  page: { key: string; slug: string; url: string; label?: string };
  /** The attempt's number; null for a 0.4.1 record, which didn't number them. */
  n: number | null;
  startedAt: string | null;
  endedAt: string | null;
  kind: ProblemKind;
  /** True when the kind came from the error's wording (a run recorded before cause codes). */
  fromWording: boolean;
  pass: PassName | null;
  step: number | null;
  command: string | null;
  /** The message with the home folder replaced. */
  message: string;
  stack: string | null;
  /** "What happened", in plain words. */
  happened: string;
  /** "What voicecap did". */
  did: string;
  /** "Did it happen again?" */
  verdict: string;
  again: "no" | "same" | "different";
  /** "Effect on the results". */
  effect: string;
  record: ProblemRecordRow[];
  /** e.g. "Not recorded: this run used voicecap 0.5.0." for the program in front, the event log, and NVDA's log. */
  notRecorded: string[];
}
export interface ProblemsSection { problems: Problem[]; line: string; unexpected: number }
export function kindFromWording(message: string): { kind: ProblemKind; pass: PassName | null; n: number | null; message: string };

export const KIND_ROWS: { kind: ProblemKind | "stopped"; title: string; whose: string; meaning: string }[];
```

**The rules:**
- **Which problems:** every failed attempt in `standing.drawnOn`, oldest first by `startedAt` (by run, then page order, for 0.4.1 records):
  - from `failedAttempts` when a page has them;
  - otherwise from `page.errors`, one problem per entry.
- **Kinds:**
  - from the attempt's `cause`, with `open-timeout`, `step-timeout`, and `page-timeout` all mapping to `timeout`;
  - for errors text, from `kindFromWording`. It recognizes the wording voicecap 0.4.1 and 0.5.0 wrote.
- **The wordings `kindFromWording` handles.** Confirm each with `git show v0.4.1:<file>` and `git show v0.5.0:<file>` (`src/drivers/guidepup-nvda.ts`, `src/drivers/guidepup/*.ts`, `src/passes/*.ts`, `src/run/page-runner.ts`), and test each with the exact historical string:
  - the outer forms, which give `pass` and `n` and pass on the inner message:
    - `Attempt <n> failed (<inner>); retrying.`
    - `<pass> pass: <inner>`
    - `Could not open the page for the <pass> pass: <inner>`
  - `lost the foreground to another window` → `foreground`;
  - `Windows is locked` → `locked`;
  - `NVDA isn't running`, `NVDA stopped running`, and `lost its connection to NVDA` → `screen-reader-stopped`;
  - `took longer than its timeout` → `timeout`;
  - an HTTP status wording → `http`;
  - anything else → `unexpected`.
- **`happened`** names the pass, the step, and the key in plain words, as in "During the read pass, at step 12 (Down Arrow)". The key names are Down Arrow for `nextLine`, H for `nextHeading`, Tab for `nextFocusable`, and Ctrl+Home for `toTop`. `openPage` reads "while opening the page for the read pass".
- **`did`:**
  - with `restarted` true: "Threw the step out, restarted NVDA and the browser, and tried again (attempt <n+1>)";
  - for `http` 5xx: "Tried again (attempt <n+1>)";
  - for the page's last failed attempt: "Recorded the page as failed";
  - for `http` 4xx: "Recorded the page as failed: trying again can't help with an HTTP 4xx".
  - Give no "of 5": the record doesn't keep the limit.
- **`verdict`:**
  - "No: read in full on attempt <k>, with NVDA and the browser started fresh." when the same run's page is done (drop the clause after "<k>" when the attempt before it didn't restart);
  - "No: read in full in run <id>." when another drawn-on run has the page done;
  - "Yes, on every attempt (<k> of <k>). That points to this page, or to voicecap, rather than a one-off." when all of the page's attempts in the run failed with this kind. For `http` and `unreachable`, the second sentence is "That points to the website."
  - otherwise "Yes, in different ways: " followed by each kind and its attempt numbers.
- **`effect`:**
  - "The transcripts shown are from attempt <k>." or "No transcripts from this run: the page failed.";
  - followed by " Partial transcripts from failed attempts are kept in attempts/<slug>/ in the run's folder." when the page has failed attempts. Don't number the folder: its numbers don't match the attempts' (plan 1's carried note).
- **`record`:**
  - for an attempt record, two rows: `startedAt` "Attempt <n> started", and `endedAt` "Failed: <cause code>: <message>". For an `unexpected` cause, a `stack` row follows.
  - for an errors-text problem, one row: time null, the entry verbatim (home replaced).
- **`notRecorded`:**
  - for every problem: "The event log and NVDA's own log: not recorded: this run used voicecap <version>.";
  - for a foreground loss, also "Which program came to the front: not recorded: this run used voicecap <version>."
  - The version comes from the run's first session's `environment.voicecap.version`, else "an earlier version".
- **`line`** (the verdict line):
  - no problems: "No problems during the runs: every page was read in full."
  - otherwise: `<count and whose>: <kinds>. <again>. <unexpected>`, where:
    - `<count and whose>` is "1 problem, outside voicecap", "2 problems, both outside voicecap", or "<n> problems, all outside voicecap" when every kind is `foreground` or `locked`, and otherwise "1 problem" or "<n> problems";
    - `<kinds>` is the plain phrases. With one kind, there's no count: "another window took the screen". With several, each has its count: "another window took the screen (2), and a step took too long (1)";
    - the plain phrases are:
      - `foreground` "another window took the screen";
      - `locked` "the computer locked";
      - `screen-reader-stopped` "NVDA stopped running";
      - `browser` "the browser stopped or didn't start";
      - `http` "the website answered with an error";
      - `unreachable` "the website couldn't be reached";
      - `timeout` "a step took too long";
      - `unexpected` "an unexpected error";
    - `<again>` is "It didn't happen again" (1), "Neither happened again" (2), "None happened again" (more), or "<k> happened again on every attempt";
    - `<unexpected>` is "It wasn't an unexpected error" (1), "Neither was an unexpected error" (2), or "None was an unexpected error" (more), followed by ", the kind that could mean a problem in voicecap itself.". When there was one: "<k> was an unexpected error, the kind that could mean a problem in voicecap itself: see its record."
- **`KIND_ROWS`:** the spec's "Kinds of problem" table, word for word, nine rows. The last is `stopped`, "Stopped by the person running it".

```ts
export type DiffLine =
  | { kind: "removed" | "added"; text: string; words: { text: string; changed: boolean }[] }
  | { kind: "same"; text: string }
  | { kind: "collapsed"; count: number };
export interface PassChange { pass: PassName; removed: number; added: number; lines: DiffLine[] }
export interface PageChange {
  key: string; slug: string; url: string; label?: string;
  passes: PassChange[];
  flags: { resolved: FlagResult[]; added: FlagResult[]; unchanged: FlagResult[] };
}
export interface Changes {
  before: RunJson;
  after: RunJson;
  changed: PageChange[];
  /** Pages read in full in both whose transcripts are identical: counted, not shown. */
  same: number;
  onlyInOne: { key: string; url: string; label?: string; reason: "new" | "no longer listed" | "failed in one run" }[];
  /** environmentDifferences(before, after), shown first when not empty. */
  tools: string[];
  /** The section's line. */
  line: string;
  /** The summary's line. */
  summaryLine: string;
}
/** The most recent counted run before `latest` with the same page source, as --compare previous picks it. */
export function runBefore(counted: RunJson[], latest: RunJson): RunJson | null;
export function changesOf(
  before: RunJson,
  after: RunJson,
  body: (run: string, slug: string, pass: PassName) => string[] | null,
  name: (page: { label?: string; url: string }) => string,
): Changes;
```

**The rules:**
- **What counts as changed:** a page done in both runs is compared pass by pass on `passes[pass].contentSha256`. Equal on every pass means `same`.
- **The line diff** is `diffArrays` over the two TXT bodies (`body` returns `extractBody` lines).
  - A removed block next to an added block is paired line by line, and each pair gets word highlights from `diffWordsWithSpace`. Unpaired lines are all `changed: true`.
  - Two unchanged lines of context are kept on each side of a change. Each longer unchanged run becomes `{ kind: "collapsed", count }`.
- **Flags** compare by `rule` and `pass`.
- **`line`:**
  - when nothing changed: "Every page read in full in both runs sounds exactly the same.";
  - otherwise "Compared with the run on <day month>: <c> of <n> pages sound different, and <s> sound exactly the same.", plus " Resolved: <for each resolved flag, its plain name on <page name> (<rule>)>." when any were resolved.
- **`summaryLine`:** "Since the last run on <day month>: <c> pages sound different" plus ", and these flags are resolved: …" when any were. When nothing changed: "Since the last run on <day month>: every page sounds the same."
- **The plain names for rules:** `generic-link-text` "the links that say only what they do, not where they go"; `unlabeled` "the unnamed controls"; `headings` "the heading structure"; `read-not-finished` "the unfinished read"; `tab-no-stops` "the missing Tab stops"; `tab-before-main` "the Tab stops before the main content"; `repeated-phrase` "the repeated speech". A custom rule uses its id.

- **`sentence` leads with the person.** Let T be the pages transcribed, P the pages in scope, and L the pages whose session answered "all".
  - L > 0: "<listeners> listened as NVDA read all <T> pages" when L = T, else "<listeners> listened as NVDA read <L> of the <T> pages".
  - Otherwise, if any session answered "part": "<names> listened to part of the runs as NVDA read <T> pages".

    - ", and reviewed every transcript" when every transcribed page's latest review is reviewed, issue, or fixed;
    - ", and reviewed <R> of the <T> transcripts" when some are;

    - "<m> page(s) has/have flags worth a closer listen." for flagged pages not cleared by a later "reviewed" entry;
    - "No flags were raised, and no issues were found." when there are neither.
  - Then "<x> page(s) couldn't be read after every attempt." when x > 0.
- **`second`:** "A human review, sped up: voicecap pressed NVDA's keys and moved from page to page; a person did the listening, the reading, and the deciding."
- **`attention`:** one line per page with flags, a failure, or an open issue, from `attentionLine`. It reads "<name>: <clauses joined by "; ">", with these clauses:

  - `unlabeled`: "<count> control(s) have no names, so NVDA says only <found>";
  - `headings`: the flag's message, lowercased after its first word ("its first heading is level 2, not 1" or "it has no headings");

  - `tab-no-stops`: "Tab reaches nothing on the page";
  - `tab-before-main`: "Tab stops before the main content, and the first stop isn't a skip link";
  - `repeated-phrase`: the flag's message;
  - a custom rule: its message;
  - a failure: "it couldn't be read after every attempt (<kind>)";
  - an issue: "a reviewer found an issue: <note>".
  - With no `found` (older records), the generic and unlabeled clauses use the flag's message.
- **`complete`:**
  - "Pages read: <T> of <P>.";

  - "Unexpected errors: none." or "Unexpected errors: <k>, which could mean a problem in voicecap itself (see Problems during the runs).";

- **`todo`:** one line each for:
  - issues found and not yet fixed;
  - pages that couldn't be read;
  - flagged pages with no decision recorded, or changed since review.
  - When there are none: "Nothing left: every issue found is fixed, every page was read, and every flagged page has a decision."

```ts
  /** The sealed run records the page draws on, exactly as on disk. */
  runs: RunJson[];
  /** Each transcript file the page shows: its run, slug, file name ("read.txt"), and exact text. */
  files: { run: string; slug: string; name: string; text: string }[];

}
/** The data as a <script type="application/json" id="fp-data"> body: JSON with every "<" written <. */
export function checkDataJson(data: CheckData): string;
/** Plain browser JavaScript (ES2020, no imports): sha256Hex(bytes), canonicalJson(value), sealOf(record), and checkAll(data, digest). */
export const CHECK_LIBRARY: string;
/** CHECK_LIBRARY, then the wiring for #fp-run, #fp-demo, #fp-result, #fp-count, and #fp-rows, as the mockup's markup names them. */
```

**The rules:**
- **`checkAll(data, digest)`** resolves to `{ files: { label: string; ok: boolean }[]; runs: { id: string; ok: boolean }[]; reviewProblems: string[]; line: string }`, where:
  - a file is ok when the SHA-256 of its UTF-8 text equals `run.pages[slug].files[name].sha256` in its embedded run;
  - a run is ok when `sealOf(run) === run.seal`;
  - review entries follow `verify`'s rules (`src/verify.ts` `chainProblems`): each sealed entry's seal, `seq` running from 1 with no gaps or repeats, entry 1's `prev` null, and each `prev` the seal of the entry before. Entries from before seals are skipped.
- **`digest`** is Web Crypto's when `crypto.subtle` exists, else the built-in `sha256Hex`.
- **`line`:** "<k> of <n> transcripts match their fingerprints, and <the run's seal checks out | both runs' seals check out | all <m> runs' seals check out>". Add ", and the review entries' seals and chain check out" when there are sealed reviews. A mismatch names each file or run in words: "doesn't match".
- **"Show a change being caught"** runs `checkAll` on a deep copy of the data with one character of the first file changed (the first character is replaced with a different one). The result names that file. The page's own data is never changed.
- **Before a click,** `#fp-run` and `#fp-demo` start `hidden`. The script un-hides them and hides the no-script line (`.fp-noscript`).
