How voicecap works

Automated checkers such as axe and Lighthouse read a page's code and test it against rules. voicecap listens instead: it takes NVDA, a free screen reader that many blind people use every day, through each page the way a person would, and saves every word NVDA says. It can spot-check a large site, zero in on the pages that need attention, or go through a whole small site. The person running it listens along, then reads the transcripts and fixes what they find: voicecap presses the keys and turns the pages, so the person can give the listening their full attention.

  1. 1. Every page on the list

    From the site's sitemap, or a list of chosen pages (a CSV file). Each page is read once, in full, or listed with the reason it couldn't be. None is missed or done twice, an easy slip when clicking through a site by hand.

  2. 2. The real screen reader

    voicecap starts NVDA, the screen reader itself, never a simulation. Every page gets a fresh browser, so no page's results depend on the page before.

  3. 3. Three ways through each page

    It presses NVDA's keys as a person would: Down Arrow to go line by line, H to go heading by heading, and Tab to go control by control.

  4. 4. Every word, and a check on every key

    It saves each key press and everything NVDA said, in order. Before and after every key press, it checks that the page still has the screen. If another window took it, that step is thrown out and the page tried again.

  5. 5. A person listens, reads, and fixes

    The person running voicecap listens as NVDA reads each page, and says so when the run ends. Then they read the transcripts, record what they found, and fix it. Flags point to moments worth a second listen.

  6. 6. A sealed record

    Every file gets a fingerprint (SHA-256), and each run is sealed. Anyone can check that nothing has changed since.

Heard on this site: its home page, three ways

NVDA's own words, from run 1402's transcripts. After each key press, voicecap waits until NVDA has been quiet for a second, so nothing it says is cut off: about 1.3 seconds a line.

Kinds of problem
What happenedWhose it isWhat voicecap does, and what it means
Another window came to the frontOutside voicecap: another program, or someone at the computerThe step is thrown out, so the other window's speech never reaches a transcript, and the page is tried again. The program's name is recorded.
The computer lockedOutside voicecap: Win+L, a screen saver, or a lock policyAs above. voicecap keeps the screen awake, but can't stop a lock.
NVDA stopped runningNVDAvoicecap can't tell why. NVDA's own log from that moment is included. NVDA is started again and the page tried again.
The browser stopped, or didn't startThe browserTried again with a fresh browser.
The website answered with an errorThe websiteA server error (5xx) is tried again. A 4xx, such as “not found”, isn't, since trying again can't help.
A step took too longNot certain: the website, NVDA, the computer, or voicecapTried again. If it keeps happening on one page, that page and voicecap's log say more.
An unexpected errorPossibly voicecap itselfThe full error, and where in voicecap's code it happened, are included. It should be reported at github.com/ICJIA/voicecap/issues.
Stopped by the person running itThe person: Ctrl+C, or closing the windowNot a failure. The page is read when the run resumes.

The evidence behind these results

2 runs, both completed and sealed. Each with who ran it, on what, when, minute by minute, and the fingerprints that tie every file to it. Anyone with the transcripts folder can check them with npx @icjia/voicecap verify --site http://127.0.0.1:4848.

What's a fingerprint? A fingerprint (SHA-256) is a code computed from a file's exact contents: change one character, and it changes completely. voicecap took one of every file as it wrote it, so a matching fingerprint shows the file hasn't changed since.

How voicecap came to be

Automated checkers are good at what a machine can test, such as a missing label or low color contrast, but they find only part of the problems. Even by Deque's count (Deque makes axe), its automated tests found 57% of the issues in its audits; the rest took a person. And no checker can say what a page sounds like: whether it reads in a sensible order, whether “Read more” makes sense out loud, or whether a form can be filled in by ear. The rest of the story, and a few things worth knowing

The usual answer is a person with a screen reader, page by page. It works, but it's slow, it's hard to show afterward exactly what was heard, and it's hard to repeat after the site changes.

voicecap keeps the person and the real screen reader, and takes over the slow parts: pressing the keys, moving from page to page, and writing down every word. It's still a listen-through, only faster, repeatable, and on the record. Working from the list also makes it more thorough than going page by page by hand: every page is accounted for, none is missed or done twice, and each is heard the same way, with the same keys in the same order. The Illinois Criminal Justice Information Authority (ICJIA) made it free, open-source software (MIT license), so anyone can read exactly how it works.

The real screen reader

It's the same NVDA a blind visitor uses, never a simulation of one, with a fresh browser for every page, so no page's results depend on the pages before it.

No page missed

voicecap works through the list itself, and the report counts every page: in scope, read, and any it couldn't read, with the reason. By hand, pages get missed or done twice.

Nothing from other windows

Before and after every key press, voicecap checks that the page still has the screen. If not, the step is thrown out.

Tamper-evident

Every file gets a SHA-256 fingerprint, the same kind of check that shows a download wasn't altered.

Both kinds of testing

This report is itself checked with axe, with no violations: the automated checker and the listen-through, side by side.

Tested itself

voicecap's own code is checked by over a thousand tests on Windows, macOS, and Linux with every change.
